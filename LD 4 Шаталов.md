# Спринт 4: Задачи Lead Developer (LD) - Постоянное хранение данных

**Исполнитель:** Шаталов Дмитрий Алексеевич  
**Проект:** Система контроля посещаемости студентов (`AttendanceControl`)  
**Роль:** Lead Developer (LD)

---

## 1. Подключение и настройка Room
В конфигурацию проекта (`build.gradle`) добавлены зависимости библиотеки **Room** (`room-runtime`, `room-ktx`) и обработчик аннотаций для генерации кода базы данных. Проект успешно синхронизирован без конфликтов версий.

---

## 2. Проектирование сущностей базы данных (Entities)
Созданы таблицы для локального хранения данных:

* **`StudentEntity`** - таблица студентов:
  * `id` (PrimaryKey, autoGenerate = true) - уникальный идентификатор студента;
  * `lastName` - фамилия;
  * `firstName` - имя;
  * `groupName` - учебная группа.
* **`AttendanceEntity`** - таблица отметок посещаемости:
  * `id` (PrimaryKey, autoGenerate = true) - уникальный идентификатор записи;
  * `studentId` (ForeignKey) - внешний ключ, связывающий отметку со студентом из `StudentEntity`;
  * `date` - дата занятия;
  * `topic` - тема занятия;
  * `status` - статус посещаемости («Присутствовал», «Отсутствовал», «Опоздал»).

Для связи `StudentEntity` и `AttendanceEntity` настроено каскадное удаление (`onDelete = ForeignKey.CASCADE`), чтобы при удалении студента из базы автоматически удалялись все его отметки.

---

## 3. Реализация слоя доступа к данным (DAO)
Реализованы интерфейсы с SQL-запросами для работы с таблицами:

* **`StudentDao`**:
  * получение списка всех студентов и фильтрация по учебной группе;
  * добавление нового студента;
  * удаление записи студента.
* **`AttendanceDao`**:
  * сохранение и перезапись отметок посещаемости за выбранное занятие (соблюдение правила одной отметки на студента);
  * выборка отметок по дате и группе;
  * получение записей для расчёта статистики.

---

## 4. Инициализация базы данных и перевод логики экранов
* Создан абстрактный класс **`AppDatabase`**, наследуемый от `RoomDatabase`, с реализацией паттерна Singleton для единой точки доступа к БД из всех Activity.
* Логика экранов работы со студентами и отметки посещаемости переведена с временного хранения в оперативной памяти (статических списков) на постоянное сохранение в локальную БД.
* Добавлена обработка пустой базы данных при первом запуске приложения, чтобы избежать падений при отсутствии записей.

---

## 5. Результат спринта
Приложение корректно собирается в Android Studio. Проверено сохранение данных после полного закрытия и перезапуска приложения на эмуляторе: добавленные студенты и проставленные отметки посещаемости сохраняются и корректно загружаются из базы.
