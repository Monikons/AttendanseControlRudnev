# Спринт 2: Требования Product Owner (Студенты и учебные группы)

## 1. Пользовательский сценарий
**Цель:** Преподаватель управляет списком студентов для дальнейшего учета посещаемости.

1. **Просмотр списка:** Пользователь открывает раздел «Студенты» и видит список учащихся с указанием группы.
2. **Добавление студента:** Пользователь открывает форму добавления, вводит **Фамилию**, **Имя**, **Учебную группу** и нажимает «Сохранить».
3. **Удаление студента:** Пользователь выбирает запись из списка, подтверждает действие и удаляет студента.

## 2. Примеры корректного и ошибочного ввода

| Поле | Корректный ввод | Ошибочный ввод | Причина отклонения |
| :--- | :--- | :--- | :--- |
| **Фамилия** | `Иванов`, `Смирнова-Петрова` | `""` (пусто), `"   "` | Обязательное поле; пробелы по краям обрезаются (`trim`). |
| **Имя** | `Алексей`, `Анна` | `""` (пусто), `"   "` | Обязательное поле. |
| **Учебная группа** | `ИС-21`, `П-302` | `""` (пусто), `"   "` | Обязательное поле. |

## 3. Системные сообщения и критерии приемки
* **Успешное добавление:** Появляется уведомление (Toast/Snackbar) *«Студент добавлен»*, поля формы очищаются, список обновляется.
* **Ошибка валидации:** Появляется сообщение *«Заполните все обязательные поля»* (или подсветка пустого поля `EditText`), запись не создается.
* **Удаление записи:** Перед удалением открывается диалог подтверждения *«Удалить студента?»*. После подтверждения выводится сообщение *«Запись удалена»*.

# Спринт 3: Задачи Lead Developer (Занятия и отметка посещаемости)

## 1. Модель данных
Для учета посещаемости в текущем сеансе создана модель данных `Attendance`.

```kotlin
data class Attendance(
    val studentId: Int,
    val lessonDate: String,
    val subject: String,
    var status: String // "Присутствовал", "Опоздал", "Отсутствовал"
)
```

## 2. Реализованные экраны и логика
* **Экран создания занятия (`AttendanceActivity` / `activity_attendance.xml`):**
  * Добавлен выбор учебной группы, ввод даты занятия и названия дисциплины.
  * При выборе группы список студентов фильтруется по полю `groupName`.
* **Список отметки посещаемости (`RecyclerView` / `Adapter`):**
  * Для каждого студента отображаются ФИО и блок выбора статуса (`RadioGroup` с тремя `RadioButton`: «Присутствовал», «Опоздал», «Отсутствовал»).
  * Выбранные статусы сохраняются при прокрутке списка.
* **Сохранение и обновление отметок:**
  * Если по комбинации `studentId + lessonDate + subject` запись уже есть в списке, она перезаписывается новым статусом без создания дубля.
  * Если в выбранной группе нет студентов, выводится сообщение *«В выбранной группе нет студентов»*.

## 3. Git и интеграция
* Код написан в ветке `feature/attendance-screen` и слит в `main` после проверки сборки.
* Статус любого студента можно менять до нажатия кнопки «Сохранить ведомость».

# Спринт 6: Задачи Lead Developer (Финальная сборка и защита)

## 1. Структура проекта
Приложение `AttendanceControl` разделено на слой данных (`data`) и слой интерфейса (`ui`):

* **`data/` (Room / SQLite):**
  * `StudentEntity.kt`, `AttendanceEntity.kt` - таблицы БД для студентов и отметок посещаемости.
  * `StudentDao.kt`, `AttendanceDao.kt` - запросы на вставку, обновление, удаление и выборку.
  * `AppDatabase.kt` - класс базы данных (синглтон).
* **`ui/` (XML + Activity):**
  * `MainActivity.kt` - главный экран меню.
  * `StudentsActivity.kt` - список студентов, добавление и удаление.
  * `AttendanceActivity.kt` - создание занятия и отметка статусов.
  * `StatisticsActivity.kt` - подсчет присутствий, опозданий и пропусков с фильтрами.

## 2. Итоговая интеграция
* **Слияние веток:** Все рабочие ветки (`feature/*`, `fix/*`) объединены в `main`.
* **Работа с БД:** Запросы к Room переведены в фоновый поток через корутины (`lifecycleScope`).
* **Проверка сборки:** Репозиторий склонирован в новую папку, проект открыт в Android Studio и собран без ошибок.

## 3. Обоснование технических решений
1. **Room (SQLite):** Выбран для локального хранения данных без интернета и проверки SQL-запросов при компиляции.
2. **Валидация ввода:** Используется `trim()` для обрезки пробелов и перезапись записи при повторной отметке студента на одном занятии.
3. **Разделение слоев:** Логика БД вынесена в `Entity` и `DAO`, интерфейс - в `Activity` и `XML`.
