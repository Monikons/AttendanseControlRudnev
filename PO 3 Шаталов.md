# Спринт 3: Требования Product Owner (Учет посещаемости)

## 1. Пользовательский сценарий
**Цель:** Преподаватель отмечает посещаемость студентов на конкретном занятии.

1. **Выбор параметров:** Пользователь выбирает учебную **группу** и **дату** занятия из доступных списков.
2. **Открытие списка:** Система загружает актуальный список студентов выбранной группы.
3. **Назначение статуса:** Пользователь проставляет статус посещаемости для каждого студента.
4. **Сохранение:** Пользователь сохраняет изменения. Система фиксирует отметки в базе данных.

---

## 2. Согласованные статусы посещаемости
Для каждого студента доступны ровно три статуса:

* **Присутствовал** - студент пришел на занятие вовремя.
* **Опоздал** - студент пришел на занятие с задержкой.
* **Отсутствовал** - студент не явился на занятие.

---

## 3. Бизнес-правила
* **Правило одной отметки:** В рамках одного занятия (комбинация `Студент` + `Дата/Занятие`) у студента может быть **только одна итоговая отметка**.
* **Перезапись статуса:** Повторное назначение статуса для того же студента на том же занятии не создает дубликат, а **обновляет (перезаписывает)** ранее сохраненное значение.
* **Обязательность выбора:** Нельзя сохранить ведомость по занятию, если хотя бы у одного студента из списка не выбран статус (или по умолчанию подставляется «Присутствовал» - *уточнить при необходимости*).
